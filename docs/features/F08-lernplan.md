## Präzisierung: interner achtsemestriger Entwicklungsweg (2026-11-23)

Die nachfolgende Reihenfolge ist die **mit dem Product Owner besprochene betriebliche Orientierung**, **keine offizielle Semesterzuordnung der BiVo**. Der Plan wird je nach Schul-/üK-Terminen, Vorkenntnissen, Förderzielen und persönlichen Wünschen verschoben, ohne den Ursprung zu verlieren.

| Semester | Schwerpunkt | Erwarteter überprüfbarer Meilenstein |
| --- | --- | --- |
| S1 | Programmiergrundlagen, Java/OOP, Problemlösen | Kleine Lösung selbst erklären; erste Tests unter Anleitung |
| S2 | Daten, APIs/JSON, AI-Modelle kritisch benutzen, Git | Externe API fachlich erklären, Ergebnisse validieren und Fehlerfälle zeigen |
| S3 | Eigenständiges, isoliertes Projekt; erste produktnahe Aufgaben | Feature mit Plan, Tests und Review nachvollziehbar liefern |
| S4 | Testing, Debugging, Qualität und Code Review | Teststrategie und aussagekräftige Regressionstests begründen |
| S5 | Prompt Engineering, AI-Ergebnisse prüfen, Vorbereitung Tagesgeschäft | AI-Unterstützung kritisch einsetzen; Sicherheits-/Qualitätsgates einhalten |
| S6 | Tägliche Engineering-Arbeit in betreuten Teamaufgaben | Jira/MR/CI-Workflow und betriebliche Standards selbständig anwenden |
| S7 | Verantwortung, Security, Planung, Kommunikation | Eigenständigen Teilbereich planen, Risiken und Reviews vertreten |
| S8 | IPA/QV-Vorbereitung, Dokumentation, Fachgespräch | Probe-IPA mit prüfbaren Artefakten und Reflexion absolvieren |

**Planmodell:** Ausgangslage, individuelle Zielstufe, Voraussetzungen, semesterbezogene Meilensteine, Bearbeiter, Änderungsgrund, verschobene Termine und nachgewiesene Ziele. Die Umsetzung benötigt explizite Zuordnung zu F06/F07, Aufgaben aus F10/F29 und Nachweise aus F11.

**Akzeptanz:** Mentor kann Meilenstein verschieben, ohne dessen Historie zu verlieren; Lernende erkennen den nächsten machbaren Schritt. Fehlende Pflichtziele bleiben sichtbar, auch wenn optionale Vertiefungen erledigt sind.
